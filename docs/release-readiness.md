# 验收与发布检查

发布由源码验证、镜像构建和目标环境验收组成。源码与镜像按发布记录分发，正式开源许可证尚未确定。每次交付记录源码版本、镜像身份与实际验证范围，使用者据此选择对应版本。

```mermaid
flowchart LR
  A[开发源码] --> B[CPU测试与干净源码包]
  B --> C[新版本镜像]
  C --> D[逐文件哈希与入口检查]
  D --> E[目标GPU沙盒验收]
  E --> F[版本验收记录]
  F -. 确定许可后 .-> G[确定公开许可证与分发信息]
  G --> H[对外发布源码与镜像]
```

## 候选包验收

- 核对产品版本、镜像 tag、不可变 image ID、源码压缩包 SHA256。
- `source-manifest.json` 中每个文件与源码包一致；核对镜像 `/opt/pipeline` 的对应文件，排除动态生成的 `image-source.json`。
- 安装器测试覆盖重复安装、身份不符、CUDA失败回滚、路径空格与命令注入边界；运行镜像不携带维护测试。
- 运行 CPU 契约测试和UI及量化/推理 Python 环境的导入检查。
- 用本地SSE服务器验证独立质量与三轮性能统计，缺失轮次不推荐；真实子进程验证断线继续、重复提交拦截与停止清理。
- 用真实交互终端检查 `quickstart`、菜单退出、无效模型路径；确认重复进入同一持久卷保留产物。
- 检查文档链接、版本、命令及默认加速说明；不把占位路径写成实际已存在模型。

仓库中 `.github/workflows/verify.yml` 与 `.gitlab-ci.yml` 执行 CPU 测试、打包及 `scripts/verify_package.py`。它不会自动建立镜像、启动 GPU 或向任何仓库发布。

## 目标 GPU 验收

依次完成 [沙盒验收指南](sandbox-quickstart.md) 的步骤，记录镜像 ID、GPU / 驱动、输入模型身份、配置与任务 ID。至少验收原模型加一种新量化、独立评分、第二阶段搜索、用户选择、真实请求与持久性。需要对外宣称支持的其他精度、GPU 或模型结构，应各自补测。

启用 MTP 时，核对性能区间的原始计数快照及差分。只有日志观察值时使用对应标记，不混为结构化区间测量。

失败时保留阶段日志、退出码、资源峰值及失败产物，使用新候选版本修复后重验；不篡改旧报告，也不清空失败事实。

## 对外发布前

| 项目 | 当前状态 / 要求 |
| --- | --- |
| 项目代码许可证 | 尚未选定开源许可证；确定后添加正式 LICENSE |
| 源码与交付镜像 | 以本次 receipt 为准，发布时同时附上文件哈希 |
| 目标 GPU 完整链路 | 以当次交付记录为准；其他GPU、模型和配方需分别验收 |
| 运行时可取得性 | 为使用者提供可访问的镜像仓库地址、访问方式或离线包 |
| 从零重建原生 CUDA/vLLM | 当前未提供完整公开构建链，不作此承诺 |
| 第三方与校准数据分发 | 保留通知，核对固定版本的数据与运行时再分发条款 |
| 用户模型、数据、凭据 | 不纳入公共源码或镜像，发布前核对交付内容 |

准备好后，发布干净源码目录、镜像仓库地址 / digest、变更记录和目标 GPU 验收摘要。镜像 push 成功、平台接收、扫描通过、GPU 推理成功分别记录。不要用可变 tag 代替不可变身份记录。

## GitLab、镜像与工作区如何对应

| 对象 | 更新动作 | 身份依据 |
| --- | --- | --- |
| 本地源码 | 修改后提交 | Git commit；未提交改动另行记录 |
| GitLab 分支 | `git push`；合并请求审核后更新默认分支 | 远端分支 commit |
| 镜像 | 从确定的源码包构建并推送 | registry digest、源码清单 SHA256 |
| 运行工作区 | 从选定镜像初始化新目录 | 工作区标记、任务冻结代码与配置 |

推送分支不等于合入默认分支；GitLab 代码更新也不会改变已有镜像、容器或任务。当前 CI 不自动构建、推送镜像。交付记录至少写明源码 commit、产品版本、镜像 tag / digest、CPU 检查和目标 GPU 验收范围，便于定位每次运行使用的版本。
