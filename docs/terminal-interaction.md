# 终端交互

InferBoost 0.5.0 使用 Rich + prompt_toolkit，适用于 SSH、网页终端和容器终端。量化与推理继续复用原有工作流，不需要额外Web服务。

## 首次启动

输入`quickstart`，先选择工作目录，检查可写性、挂载信息与磁盘空间，再自动显示内存/GPU。发现挂载不等于已确认跨实例持久，仍需核对平台配置。模型路径单独输入；识别架构、精度、大小、已有量化和MTP张量后才选择配方。

宽终端显示字符标识，颜色区分当前项、说明、错误；终端不能只放大某一行字体。`NO_COLOR=1 quickstart`关闭颜色。`quickstart --plain`保留数字菜单；`TERM=dumb`也使用兼容入口。非交互CLI输出纯文本日志。

## 操作

| 场景 | 操作 |
| --- | --- |
| 路径输入 | Tab补全；显示最近模型路径 |
| 输入框 | Enter保留当前值，`:b`返回，`:q`回菜单，`:clear`清空可选项 |
| 单选/多选 | ↑↓移动，Space勾选，Enter确认，直接打字搜索，Esc返回 |
| 错误或不兼容 | 错误保留在当前步骤；不兼容配方显示原因并禁止选择 |
| 最后确认 | 查看模型、预算、资源提示、真实命令与输出目录；可返回修改 |

支持快速体验、标准对比、自定义模式。快速体验默认10条评测、64条校准、1轮性能及缩小搜索预算，所有报告标明“链路验证”。标准第一阶段独立评分1次，性能3轮。自定义可改配方、校准、重复次数和搜索预算。资源参数在高级配置中调整，见[配置指南](configuration.md)。

## 更换存储路径

主菜单选择 **工作目录 · 更换存储路径**；数字菜单是 **7**。也可直接运行：

```bash
quickstart workspace
# 兼容无颜色的数字交互
quickstart workspace --plain
```

1. 输入新路径，或从最近目录中选择；支持 Tab 补全及带空格路径。
2. 查看目标目录、剩余磁盘、挂载点与持久性提示。
3. 确认后初始化并进入新目录的主菜单；Esc / `:b` / `:q` 可以返回。

切换只改变随后任务的存储位置，不移动模型、缓存或报告，也不停止旧目录中的后台任务。任务中心显示当前目录的任务；切回原目录即可继续查看。需要搬迁已有任务时应单独处理路径依赖，不应直接移动正在运行的目录。

目标必须是新空目录或本镜像同版本、源文件校验通过的工作目录。模型目录、非空普通目录、互相嵌套的工作目录、其他版本或已修改的代码目录不会被覆盖。升级镜像请选择新空目录；主菜单“从旧工作目录重新选模型”可复用完整量化结果，进入新的加速任务。

目录选择写入当前用户的 `~/.config/inferboost/workspace.json`。未显式覆盖工作目录时，下一次全局 `quickstart` 使用这个选择；显式 `PIPELINE_WORKSPACE` 优先。如果原终端导出过旧路径，切换页面会打印新的 `export` 命令，需要在终端更新。主目录未持久挂载时，重建容器后偏好可能丢失；权重与报告的保留取决于工作目录挂载。再次进入的可靠命令是：

```bash
export PIPELINE_WORKSPACE=/mnt/persistent/my-workspace
quickstart
```

这些路径必须在容器内可访问；菜单不会新增宿主挂载。Docker 安装器用户在已挂载的 `/workspace` 下选并列子目录；更换宿主磁盘仍需重新配置容器挂载。

源码开发的 `./quickstart` 以所在源码目录为工作目录，不随环境变量切换，也不自动复制开发依赖。需要独立存储时使用独立源码副本，在其中启动；镜像用户使用全局 `quickstart workspace`。

## 看板

确认后提交独立后台进程，显示当前阶段、真实计数、耗时、GPU显存、容器内存与剩余磁盘。成功、准备完成、跳过和失败分别计数；不知道后端总量时只显示状态，不编造百分比或ETA。

- Q / Ctrl+C：退出查看，任务继续。
- L：展开 / 收起实时日志；顶部状态固定，下方每秒刷新最新最多 50 行，短终端自动减少显示行数。Tab 切换主日志和当前阶段详细日志，Enter 收起；完整日志保存在磁盘。
- R：查看已生成结果；Markdown / HTML / JSON同时保留。
- C：在选择点选模型/配置，或在停止后续跑。
- S：确认停止；保留已完成结果，清理该任务正常管理的服务。

终端断开不停止后台任务。容器重启会终止进程；重新挂载原卷、使用相同源码版本后从任务中心继续。恢复以完整候选/阶段为单位，不承诺量化中某一层恢复。异常强杀后遗留服务需结合日志与GPU空闲检查处理，不能保证任何系统崩溃都自动清理。

直接`quickstart workflow ...`及`--plain`数字菜单仍前台执行，没有独立后台任务的断线保障。

## 结果如何读

第一阶段表展示算法与W/A精度、本测试集得分、权重大小、采样显存峰值、TTFT、E2E、TPS。标准性能每轮先求相同样本的均值，再对轮次等权平均；±表示轮均值的样本标准差，不是置信区间。cold/warm分开记录，预热另存并排除。100题测3轮仍是100个独立问题，不是300题。

质量使用独立请求，temperature=0、seed=0，不承诺所有GPU计算逐位确定；默认不为同一批确定性规则题重复三次评分。第二阶段仍保留原协议的独立质量复核。

推荐理由按质量/延迟/权重大小偏好解释，默认用户最终选择。失败、不完整、无评分依据的候选不会被自动推荐为已验证方案；快速体验不构成正式部署推荐。

## 版本与环境

镜像UI环境为`/opt/inferboost-ui`；量化和推理环境独立保留。源码用户安装`requirements/terminal.lock`后可运行`./quickstart`；无依赖时降级为数字菜单。

升级使用新的`PIPELINE_WORKSPACE`，旧实验继续保留其原代码、权重和记录。工作区标记或源码身份不一致时拒绝覆盖，避免把不同版本结果混在一起。

## 已有任务的独立只读查看器

任务使用冻结源码。需要给已有任务单独升级查看界面时，将新版 `scripts/watch_live.py` 和 `pipeline/dashboard.py` 放到工作区外的同一工具目录，在原任务容器中运行：

```bash
/opt/inferboost-ui/bin/python /tools/inferboost/watch_live.py \
  --root /path/to/original-workspace --run-id task-name
```

该入口只读取状态和日志，不改原任务配置或源码，也不提供停止、选择和续跑操作。常规新任务仍使用 `quickstart`。
